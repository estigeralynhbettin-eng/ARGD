# Public release provenance

This public release was prepared from the R38 submission supplementary materials on 8 November 2026. The seven supplementary filenames retain their S1 to S7 identifiers. The author's retained submission packages remain the provenance source for the original records.

## Publication changes

S1, S2 and S4 preserve their submission-package bytes. S1 supplies metadata and author-created checks with the source-attribution policy already retained. S2 supplies the four-row repair-coverage matrix. S4 preserves the original evaluator responses, challenge evidence, historical comparison targets and offline audit program, together with its applicable upstream notices.

S3, S5, S6 and S7 are public derivatives. Machine-local Windows and Linux workspace-root strings are replaced by the literal `PUBLIC_PATH_REDACTED/` prefix while retaining their relative suffixes. The changes concern source locators, execution-environment properties, recorded command paths and historical documentation. These markers identify redacted historical roots. Readers should map them to their own separately obtained source checkouts when inspecting command provenance.

The public S3 copy omits an internal matrix-review PDF and an internal independent-review Markdown report. The retained matrix CSV, Java test source, fixture excerpts, numerical results and test outcomes remain available. The two original Java matrix/adapter test files and the four/six-input fixture excerpts retain their source bytes. The S3 JUnit index distinguishes original-source hashes from the hashes of the public XML copies.

The generic temporary-directory literals inside one original S4 model-proposed code fragment are retained as response evidence. They identify example runtime paths within the generated text. The evaluator records and their byte-preservation provenance remain unchanged.

The S6 figure PDFs, native editable drawings, numerical observation columns and plotting programs are retained. Source-locator path strings in plotting metadata and a historical script-comment locator are normalized. Figure generation reads the supplied local plotting data.

All record counts, test names, assertions, source commit and source identity hashes, scenario identifiers, observed decisions and test results are preserved. The public package manifests describe the published bytes. Hashes retained in source-identity fields describe their historical originals. `PUBLICATION_CHANGES.csv` records modified or omitted archive members using member-relative names, original hashes and public hashes. `SUPPLEMENTARY_SHA256.csv` records original submission ZIP identities and current public ZIP identities.

## Offline checks

Extract S4 and run `python verify_evaluator.py --output evaluator_audit_output` from its extracted directory to validate the manifest and recompute the archived-record analysis with the Python standard library. Extract the nested legacy ZIP inside S3 and run `python verify_package.py` from that extracted directory to validate its manifest and retained matrix observation mappings. These programs inspect archived evidence and produce integrity or analysis outputs.

The public-copy preparation performed integrity, parsing, outcome-preservation and deterministic offline record-audit checks. The archived vulnerability executions and model generations retain their original scope and evidence limits.
